## 一、这套系统给你带来什么

### 以前的送货是个"黑盒"

顾客在小程序下单、付款，你在后台看到订单，打包好，骑上电动车出门。从这一刻起：

- **顾客不知道**你出发了没有、走到哪了、几点能到，只能打电话问
- **系统不知道**这单送到哪一步了，只能等你回来手动点一下"已完成"
- **你自己也没数**：今天跑了多远、哪些小区最耗时间、哪一单快超时了，全凭脑子记

### 现在变成什么样

| 场景 | 以前 | 现在 |
| --- | --- | --- |
| 顾客想知道货到哪了 | 打电话问你 | 打开小程序，地图上能看到送货的人在哪、大概几点到 |
| 一次要送好几单 | 自己想先送哪家 | 系统自动排好顺序，冷冻的排在前面，绕路最少 |
| 送到了 | 回店里在后台点"完成" | 手机上滑一下 + 拍张照，订单自动变"已完成"，顾客小程序同步更新 |
| 遇到麻烦（人不在家、地址错） | 打电话回店里说 | 手机上点一下上报，后台立刻看到，有照片有记录 |
| 想知道经营情况 | 没数 | 后台有准时率、平均送达时长、哪栋楼最难送的排行 |
| 忘了哪单还没送 | 靠记性 | 调度台四个队列一眼看完，快超时的自动标红 |

### 一句话总结

**顾客能看见货在哪，你能看见每一单卡在哪，送货顺序不用自己动脑子。**

## 二、四个部分分别是什么

这套系统由四块拼起来，缺一块就不完整。

| # | 名称 | 通俗解释 | 装在哪 | 谁用 |
| --- | --- | --- | --- | --- |
| 1 | **后端服务器** | 系统的"大脑"。所有数据都存在这里，派单、算路线、算送达时间都是它干的 | 你租的那台云服务器（现在跑着的那台） | 没人直接用，其他三块都连它 |
| 2 | **管理后台** | 你用电脑打开的网页，管商品、管订单，现在多了"配送调度台" | 服务器上，用浏览器访问 `https://hqhjxt.vip` | **店主（你）** |
| 3 | **微信小程序** | 顾客用来下单的那个小程序，现在多了实时配送地图 | 微信里 | **顾客** |
| 4 | **骑手 APP** | 装在送货人手机上的安卓应用，叫「禹邻优鲜骑手」 | 送货人的安卓手机 | **送货的人（现在就是你自己）** |

它们之间的关系：

```
        顾客手机（微信小程序）
              ↓ 下单
        ┌─────────────────┐
        │   后端服务器     │ ← 你的电脑（管理后台网页）
        │   （云服务器）   │
        └─────────────────┘
              ↕ 派单 / 上报位置
        送货人手机（骑手 APP）
```

### 一个必须知道的前提

**骑手 APP 只能装在安卓手机上，苹果手机（iPhone）用不了。**

原因：苹果的应用必须上架 App Store 才能安装，上架需要公司主体、开发者账号（每年 688 元）和一到两周的审核。安卓可以直接把安装包发给手机装上，不需要审核。

如果以后送货的人只有苹果手机，需要另外买一台便宜的安卓手机做"送货专用机"（千元机就够用），或者重新走苹果上架流程（另算工期和费用）。

## 三、现在能用什么

下面这些都已经做好了。**服务器那一侧的每一项都有自动化测试盯着；手机 APP 这一侧是人工验证的**，两者的把握程度不一样，原因见第七节。

### ✅ 后端服务器

- 自动派单：订单打包好之后自动生成配送任务，自动分配给在岗的送货人
- 自动合单：地址挨得近、时间不冲突的几单会自动打包成"一趟"，一次带出去
- 自动排顺序：一趟里先送谁后送谁由系统算，8 家以内算的是**绝对最优解**（把所有可能的顺序都试一遍挑最好的），超过 8 家用快速算法
- 冷冻优先：带冷冻/冷藏商品的单不会被排在最后一站，避免化掉
- 预计送达时间：会根据距离、路况习惯、**这栋楼以前送了多久**来算。同一栋楼送得多了，估得越准
- 位置追踪：送货人的位置每 10～60 秒上报一次（骑车时勤一点，站着不动时省电）
- 异常处理：13 种常见问题（联系不上、地址错、破损、漏液、拒收……）都能一键上报
- 送达凭证：每张照片自动带时间和地点水印，存在服务器上可以随时翻出来
- 称重留痕：拣货时填的件数、总重和拣货备注会永久留在这一单的记录里，顾客有疑问时能调出来对（**注意：目前没有上传电子秤照片的地方**，只能靠填写，见第七节）

### ✅ 管理后台（左侧菜单新增 8 项，另有 2 个二级详情页）

| 页面 | 干什么用 |
| --- | --- |
| **配送调度台** | 主界面。四列队列 + 地图，看今天所有配送情况 |
| 配送任务 | 查某一单送到哪一步了，看照片、看时间轴 |
| 配送波次 | 查"一趟"里有哪几单，什么顺序（点开是**波次详情**，可以拖拽改顺序） |
| 骑手管理 | 加人、改资料、重置密码、停用账号（点开是**骑手详情**，有班次历史和轨迹回放） |
| 异常处理 | 处理送货人上报的问题 |
| 骑手结算 | 算配送费用的（你的场景用不上，见第五节） |
| 配送分析 | 准时率、平均时长、楼栋难度排行 |
| 调度参数 | 改门店坐标、改各种规则 |

### ✅ 微信小程序（顾客侧）

- 订单详情页在"配送中"时显示**实时地图**，送货人的图标会平滑移动（不是一跳一跳的）
- 显示**预计送达时间区间**（比如"预计 14:20-14:30 送达"），而不是一个精确到分钟的时间——区间更容易做到，顾客也更不容易失望
- 五步进度条：已安排骑手 → 已取货 → 配送中 → 即将送达 → 已送达
- 显示"骑手还有 N 单送到你"
- 送达后可以给这次配送打分（1-5 星 + 标签）
- 可以直接打送货人的电话

### ✅ 骑手 APP

- 手机号 + 密码登录，第一次登录强制改密码
- 上班 / 下班开关（**只有点了"上班"才会给你派单**）
- 任务列表：待接单 / 进行中 / 今日已完成
- 新单语音播报，会重复播直到你确认
- 取货核对：一趟几单几件，逐单打勾
- **送达必须拍照**（你要求的），滑动确认，防止误触
- 异常上报：13 种类型，选一个 + 拍照 + 打字
- 地图和导航（⚠️ **这一层还没有在真手机上跑过一次，拿到安装包后第一件事就是验证它**，见第七节）
- **保活向导**：覆盖小米、华为、荣耀、OPPO、vivo、三星、魅族、努比亚、中兴、传音、联想 11 个品牌，教你怎么设置手机才不会把 APP 杀掉
- **没网也能用**：所有操作先存在手机里，有网了自动补传

## 四、还需要你做什么

⚠️ **这一节最重要。下面的事情不做完，系统装上了也跑不起来。**

### 🔴 必须做（不做系统不能用）

> 其中第 2 条是**已经做完**的，留在这里是因为它是整套系统的总开关——你需要知道它有多重要，并在上线当天在页面上确认一眼。

#### 1. 🥇 上线前先把数据库备份下来 —— **这是第一件事，排在所有事情前面**

| 项目 | 说明 |
| --- | --- |
| 这是什么 | 在重启服务器程序**之前**，把整个数据库导出成一个文件、单独存好 |
| **为什么排第一** | 这次上线，程序要在你的正式数据库上新建 27 张表。这个"程序启动时自动建表"的动作，在你的正式数据库上是**第一次真正执行**——以前的版本因为打包时漏装了一个必需的零件，这套机制其实一直没运行过；更麻烦的是它不工作的时候一声不吭，日志里什么都不写，所以一直没人发现。零件现在补上了，这次它会真的动手 |
| 风险到底有多大 | 不大，但不是零。它做的事全部是"新增"——建新表、写默认配置，**不修改、不删除任何老数据**；而且已经用两种数据库排练过（一个空库、一个和你正式库起始状态一样的库），两次都一次通过。但排练库里没有你的真实订单，"第一次"这三个字本身就意味着必须准备后悔药 |
| 怎么做 | 技术人员执行，5～10 分钟。命令在《安装部署手册》2.2 节 |
| **怎么算做完了** | 备份文件存在、不是 0 字节，**并且已经往一个临时数据库里真的导入成功过一次**。没验证过的备份不算备份——文件损坏、导出中断都是真实发生过的事，而且只有在真需要它的时候才会发现 |
| 不做会怎样 | 万一建表过程出意外，**没有任何办法回到上线前的状态**。订单、顾客、商品、支付记录全部只存在这一个数据库里 |

⚠️ **顺序不能反：先备份，后重启。** 程序一旦启动，建表动作就已经发生了，那时候再想备份"上线前的样子"已经来不及。

#### 2. ✅ 订单页的「拣货完成」按钮 —— 已经做好了，上线后确认一眼就行

| 项目 | 说明 |
| --- | --- |
| 这是什么 | 后台"订单管理"页面上，原来那个「配送」按钮，现在显示成「**拣货完成**」 |
| 为什么重要 | **整套配送系统的开关就是这个按钮。**你不点它，系统不会生成配送任务，不会派单，送货人手机上永远收不到单 |
| 现在的状态 | **已经做好了，不需要再找人开发。**点它会弹出一个确认框（填件数、总重、冷链等级、拣货备注），确认之后立刻生成配送任务并自动派单；勾选好几单还能用「批量拣货完成」 |
| 你要做的 | 上线当天打开「订单管理」看一眼：「备货中」的订单那一行，显示的应该是绿色的「拣货完成」。**如果显示的还是「配送」**，说明「自动派单」总开关被关掉了，去调度台右上角把它打开 |
| 怎么用 | 见《日常使用手册》1.2 节「第 ⑤ 步」，那一节讲得最细 |

#### 3. 把门店坐标改成真实位置

| 项目 | 说明 |
| --- | --- |
| 这是什么 | 系统里现在填的是"兴泾镇中心"的大概位置，不是你店铺的准确位置 |
| 为什么必须 | 所有的距离、路线、送达时间都是从店门口开始算的。坐标偏 500 米，每一单的预计时间都会偏 |
| 怎么做 | 手机打开高德地图 → 长按你店铺的位置 → 弹出的框里能看到经纬度 → 抄下来 → 后台「调度参数 → 门店」里填进去。**详细步骤见《日常使用手册》1.6 节** |
| 花多长时间 | 5 分钟 |
| 不做会怎样 | 预计送达时间不准，地图上店铺图标位置不对，"远单"标记会乱标 |

#### 4. 给送货的人建账号

| 项目 | 说明 |
| --- | --- |
| 怎么做 | 后台「骑手管理」→「新增骑手」→ 填姓名、手机号、车辆类型 → 保存后系统会**显示一次初始密码** |
| ⚠️ 注意 | 初始密码**只显示这一次**，关掉窗口就再也看不到了。一定要当场抄下来。忘了只能点"重置密码"重新生成 |
| 不做会怎样 | 送货人没法登录 APP |

#### 5. 在送货人的手机上做完「保活向导」

| 项目 | 说明 |
| --- | --- |
| 这是什么 | 国产安卓手机为了省电，锁屏一会儿就会把后台的 APP "冻结"掉。冻结之后：位置不上报了、新单收不到了。保活向导就是教你一步步把这些限制关掉 |
| 怎么做 | APP 里「我的 → 设置 → 保活向导」，跟着一步步点。**必须在手机上真的点一遍，不能只是看看** |
| 花多长时间 | 15 分钟左右，一台手机只需要做一次 |
| 不做会怎样 | **这是最常见的故障原因。**骑上车锁屏几分钟，位置就停在原地不动了，顾客看到骑手"卡住"了；更严重的是新订单收不到 |

#### 6. 技术人员打一个正式安装包，并且**先在一台真手机上验证**

| 项目 | 说明 |
| --- | --- |
| 为什么 | 送货人手机上装的那个 APP，得有人先打包出来。**签名已经配好了**（这次交付里做完的，不用再折腾），打包基本就是一条命令；要注意的是必须打"正式版"——"调试版"连的是开发用的地址，**连不上你的服务器** |
| 怎么做 | 技术人员按《安装部署手册》第六节执行，一次性工作 |
| 🔴 **最要紧的一条** | 打出来之后**必须先装到一台真的安卓手机上跑一遍**，不能只在电脑的模拟器里试。原因见第七节「还有四件事」的第 2 条 |
| 🔴 签名文件和密码单必须备份 | 签名文件（`rider-release.jks`）加上它的口令，是这个 APP 唯一的"身份证"。**任意一样丢了，就永远没法给这个 APP 发更新**：以后修 bug、加功能，打出来的新包都装不上老手机，只能让每个人卸载重装、手机里没传完的数据全部清空。让技术人员把文件拷到 U 盘和网盘各一份、口令另存一份（**两样分开放**），**并且都交一份给你自己收着** |
| ⚠️ 换电脑打包要多两步 | 为了不让签名口令跟着代码到处传，签名文件和写着口令的那个配置文件**都没有放进代码仓库**。所以换一台电脑打包时，技术人员要先从备份里把这两样放回去，才能打出能装的包。**漏了这一步不会报错**，只会打出一个装不上手机的包——《安装部署手册》6.1 节写了怎么查 |

### 🟡 建议做（不做也能用，但会有缺陷）

| # | 事项 | 做了会怎样 | 不做会怎样 |
| --- | --- | --- | --- |

## 五、因为你的情况关掉了哪些功能

这套系统原本是按"雇一队骑手"的规模设计的，很多功能对"自家人送货"来说是累赘。下面这些已经关掉了：

| 功能 | 原本是干什么的 | 为什么关掉 | 现在的表现 |
| --- | --- | --- | --- |
| **疲劳管控** | 连续跑 4 小时强制休息、8 小时弹窗、12 小时强制下班 | 你自己家的生意，忙起来没法被系统踢下线 | 完全不触发。APP 班次页连提示条都没有 |
| **骑手计价 / 结算** | 按里程、楼层、天气算配送费，生成结算单 | 钱是你自己的，左手倒右手没意义 | **APP 里没有"结算详情"这个页面，也没有入口。**后台"骑手结算"页面还在，但你可以完全不管它 |
| **服务分** | 超时扣分、准时加分，分数影响派单优先级 | 一个人送货，给自己打分没意义 | **APP 里没有"服务分"这个页面，也没有入口** |
| **申诉** | 对扣分、超时判定提出申诉 | 没有扣分就没有申诉对象 | **APP 里没有"申诉"这个页面，也没有入口** |
| **隐私号** | 给顾客和骑手之间接一个虚拟号码，互相看不到真实号码 | 你说了顾客手机号不用隐藏 | 送货人在 APP 里直接看到并拨打顾客的真实手机号 |
| **健康证校验** | 健康证过期就不许上班 | 各地规定不一样，你自己送货 | 关闭。骑手资料里还是可以填健康证有效期，只是过期不拦你 |
| **送达核销码** | 顾客报一个 4 位码，骑手输进去才算送达 | 增加麻烦，自家送货没必要 | 关闭。**但送达拍照是开着的**（你要求的），不拍照划不动送达 |

### 以后想开怎么办

上面这些**除了最后要说的三项，都是"代码全都在，只是参数关掉了"**，不需要重新开发。

## 六、关于高德地图 Key

### 现在没有 Key，有什么影响

先说结论：**不影响使用，只影响精度和好看程度。**

| 地方 | 有 Key | 现在（没 Key） |
| --- | --- | --- |
| 顾客小程序的地图 | 正常 | ✅ **正常**。微信小程序的地图是微信自带的，不需要高德 Key |
| 后台调度台的地图 | 显示地图底图、店铺和骑手图标 | ⚠️ 地图区域显示"未配置地图 Key"的提示页。**四列队列、派单、改派全都正常**，只是看不到底图 |
| 骑手 APP 的地图页 | 显示地图 | ⚠️ 地图出不来。**导航按钮仍然能用**——会自动跳转到手机上装的高德或百度地图 APP 去导航 |
| 距离和里程 | 按真实道路算 | ⚠️ 用**直线距离 × 1.35** 估算。举例：直线 1 公里的地方，系统当成 1.35 公里。市区路网规整时误差不大，遇到河、铁路、大院子绕行时会偏小 |
| 预计送达时间 | 更准 | ⚠️ 会跟着里程一起偏。但系统有"保底时间"兜底，不会算出离谱的乐观时间 |
| 送货顺序优化 | 按真实路程排 | ⚠️ 按直线距离排。**兴泾镇范围小，实际影响很小** |
| 天气补贴 | 自动识别下雨下雪 | ⚠️ 永远当成晴天。反正你也不算配送费，无所谓 |

**简单说：现在就能用，用起来也不会觉得少了什么，就是后台和 APP 的地图是空的，里程数字是估的。**

### 以后想加，怎么加

高德的**个人认证 Key 是免费的**，每月 15 万次调用额度，你这个店量用不完。申请要实名认证，大概 1 天。

拿到 Key 之后，有四个地方要配（其中第 2 步你自己在后台就能做，另外三步要技术人员）：

| 序号 | 配哪 | 做什么 | 生效范围 |
| --- | --- | --- | --- |
| 1 | 服务器环境变量 | 填 `AMAP_WEB_KEY`，把 `AMAP_ENABLED` 改成 `true`，重启服务 | 距离和里程改成走真实道路 |
| 2 | 后台「调度参数 → 地图」 | ✅ **这一步现在不需要技术人员了。**装系统的时候已经自动准备好了「JS API Key」和「Web 服务 Key」两个空位（后台「调度参数」里会有一个"地图"分类），你自己把 Key 填进去保存即可，以后换 Key 也一样 | 后台调度台的地图能显示 |
| 3 | 后台「调度参数 → 路径」 | 「距离矩阵提供方」从 `HAVERSINE` 改成 `AMAP` | 让系统真的去用高德算距离 |
| 4 | 重新打包骑手 APP | 打包时带上 Android 端的 Key，重新装到手机上 | APP 里的地图能显示 |

⚠️ 三个 Key 是**不一样的三把钥匙**，不能混用：服务器用"Web 服务 Key"，后台网页用"JS API Key"，手机 APP 用"Android Key"。在高德开放平台的同一个应用下可以一次申请三个。

### 还有四件事，也得跟你说清楚

上面那张表列的是"**功能上没有的**"。下面这四条不一样：功能都在、今天也照样能开张，但它们各自藏着一个**以后可能变成麻烦的地方**。与其等出事再解释，不如现在说明白。

#### 1. 手机 APP 这一侧，一个自动化测试都没有

"自动化测试"就是一批替人干活的检查程序：每改一次代码，它们自动把功能全跑一遍，哪里改坏了立刻报出来。

- **服务器那一侧有四百多个**（具体条数以实际运行结果为准），每次改动都会全部跑一遍。所以后端改坏了东西，基本当场就能发现
- **手机 APP 这一侧一个都没有**，全靠人工在电脑的模拟器上一屏一屏点

这意味着：**以后 APP 每改一次，"改好了 A 却碰坏了 B" 的风险，比服务器那边高得多**，而且只能靠人再点一遍才能发现。所以 APP 每次有新版本，都建议按《日常使用手册》第二部分从登录、上班、接单、送达完整走一遍再交给送货的人，别直接换上就用。

#### 2. 地图和导航那一层，从来没有真正运行过一次

这条比之前说的"只在模拟器上验证过"还要严重，得说清楚。

电脑上的模拟器用的是电脑的芯片（x86_64 架构），而安装包里高德地图那部分的库文件，**只提供了手机用的 arm 架构版本**。两边对不上，结果是：**地图、导航、高德定位这一整层，在模拟器上压根没有被执行过，一次都没有。**

也就是说，这不是"没在真机上再复核一遍"，而是"**根本没跑起来过**"。

🔴 **所以拿到安装包后的第一件事，必须是装到一台真的安卓手机上验证**，重点看四样：APP 打得开不闪退、能登录能上班、上班后后台看得到位置在动、点「导航」能跳到手机上的高德或百度地图。（地图页面本身是空的属于正常——还没申请地图 Key，见第六节。）

这一步没做之前，不要把手机交给送货的人。

#### 3. 出了问题，能"退回去"的时间窗其实很短

系统会自动备份：**数据一变就存一份**（停下来 1.5 秒后触发），另外**每 5 分钟固定再存一份**。听起来很密，但有一个关键限制：

> **只保留最近的 30 份，超过就把最老的删掉。**

忙的时候，30 个位置**两三个小时就轮完一圈**了。也就是说：

- 上午出的问题，下午才发现 → **很可能已经没有能退回去的备份点了**，因为出问题那一刻的备份早被新的挤掉了
- 越忙的时候，这个窗口越短

**能做什么**：

- 做**大动作之前先手动备份一次**（后台「数据备份」页面），比如批量改价、批量改商品、清理数据
- 发现不对劲**当场就去看备份页面**，别拖到收工后
- 上线第一周按建议做一次"备份 + 恢复"演练，真出事时才知道怎么救

> ⚠️ **挑恢复点的时候，看页面列表的顺序，别去读文件名上的时间。** 这次升级把备份文件名里的时间改成了北京时间，**升级之前生成的那些旧备份，名字上的时间比实际早 8 小时**，新旧混在一起时按文件名排先后会排错。页面列表本身是按实际生成时间排的，最上面永远是最新的一份，照着它挑就不会错。详见《常见问题》「数据会不会丢」那一条。

#### 4.（提醒）「自动派单」开关不要随便关

后台调度台右上角那个「自动派单」，现在管着两件事：关掉它不光是"不自动派单"，**订单页上的「拣货完成」按钮也会一起消失**，变回原来的「配送」。那样就连配送任务都建不出来了，等于整套配送停摆，页面上还不会有任何提示。

想让某一单马上出发，用「待派积压」里那一单的「立即派单」就行，别动这个总开关。详见《日常使用手册》1.7 节。
