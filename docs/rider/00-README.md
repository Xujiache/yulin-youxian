# 禹邻优鲜 · 骑手端（商家自配送）项目文档

本目录是「骑手端 + 智能配送调度」整体方案的**唯一事实来源**。所有并行开发的 Agent 都必须以本目录中的文档为准，不得自行发明表结构、接口路径或状态枚举。

## 一句话目标

给现有的「单门店生鲜同城配送系统」增加一套**原生 Android 骑手端**和**服务端智能调度中枢**，让门店自有骑手接单、自动规划多点配送路线、实时上报位置，让顾客在微信小程序上看到骑手的实时位置和预计送达时间。

## 现有系统的关键事实（先看这个，否则会写错）

这套系统和常规 Spring Boot 项目**很不一样**，动手前必须知道以下六条：

1. **后端没有 ORM，也没有业务关系表。** 全部业务数据（商品、订单、地址、退款、设置）都以 JSON 文档形式存在 MySQL 的 `application_state` 表的**三行**里（`storefront` / `user-profiles` / `printing`）。`StorefrontService` 把它们全量加载进内存的 `LinkedHashMap`，每次改动都调用 `persist()` 把**整个快照**重新序列化写回。
2. **因此高频写入绝对不能进快照。** 一次 `persist()` = 复制全部集合 + 全量 JSON 序列化 + SHA-256 校验 + 回读校验 + 影子写 JSON 文件 + 触发防抖 ZIP 备份，而且方法是 `synchronized` 的。骑手 GPS 上报如果走这条路会直接压垮服务。**骑手域必须使用真正的关系表**，这是本项目最重要的架构约束。
3. **订单状态是中文字符串字面量**，没有枚举：`待支付` / `已支付/待接单` / `备货中` / `配送中` / `已完成` / `已取消` / `已关闭` / `退款中` / `部分退款` / `已退款`。改动它们会牵动几十处 `String.equals`，**不要改**。
4. **没有 Spring Security，没有 JWT。** 鉴权是两个 `HandlerInterceptor` + 内存里的 `ConcurrentHashMap<String, Session>`，令牌形如 `wx_<uuid>` / `admin_<uuid>`，**重启即全部失效**。骑手端不能沿用这个模式（骑手不能每次服务重启就被登出）。
5. **完全没有实时推送。** 没有 WebSocket、没有 SSE、没有 MQTT、没有微信订阅消息。唯一的「准实时」是打印代理的 HTTP 轮询租约模式，这是本项目已被验证的外部设备接入范式。

6. **现有平台没有配送范围。** `SettingsDto` 里没有该字段，后端也没有任何距离校验代码，顾客可以在任意地址下单。**配送域必须与之一致：平台内所有订单都要派送，不做距离筛选。** 所有涉及距离的配置项都是软约束，只影响「怎么派」，不影响「派不派」。这是最容易被写错的地方，详见 05 文档 §4.7。

已有的可复用资产：地址表已经存了经纬度（`AddressDto.latitude/longitude`，目前只存不用）；`DeliveryAddressIntelligence` 已经能解析中文地址的楼栋/单元/楼层/房号并给出步行顺序；配送时段、配送费与免配送费活动、批量备货/配送都已具备。

已知的既有缺陷（不是本项目引入的，但要知道）：配送时段的 `maxOrders` 字段**存了但从未被任何代码校验**，时段容量目前是无限的。

## 命名与风格约定

- 文档、注释、UI 文案一律**中文**。
- 提交信息遵循 Conventional Commits（`feat:` / `fix:` / `refactor:` / `docs:` / `test:` / `chore:`），可带 scope，例如 `feat(dispatch): 新增顺路度评分`。
- 后端 Java **不写代码注释**（现有 `server/src/main/java` 全域无注释，这是既定风格）。复杂逻辑用清晰的方法名和单元测试表达。
- Android/Kotlin 与 Vue/TS 可写必要注释，但只解释「为什么」，不解释「做了什么」。
- 金额一律 `int` 分；距离一律 `int` 米；时长一律 `int` 秒。
- 坐标系一律 **GCJ-02**（高德与微信小程序 `<map>` 都用它，全链路不做转换）。
- 时区一律 `Asia/Shanghai`。

## 范围边界

**做**：骑手账号与排班、智能派单、合单与波次、多点路径规划、实时轨迹、顾客可视化、异常上报、凭证留存、收入结算、服务分、消息推送、调度看板、疲劳与合规管控。

**不做（一期）**：多门店、多租户、第三方运力接入（预留接口不实现）、骑手众包招募与结算开票、司法级电子存证、离线地图下载。

**Android 骑手端不做**：抢单大厅（本项目是门店自有骑手，系统统一派单，对齐盒马/朴朴模式，而非美团众包模式）。
