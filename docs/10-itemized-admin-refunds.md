# 按商品主动退款

## 操作方式

管理后台「订单中心 → 售后退款 → 主动退款」：

1. 输入订单 ID 或订单号，点击「查找订单」。账号 ID 可以用于核对所属客户。
2. 勾选一个或多个商品。默认不勾选，避免误退整单。
3. 每个商品默认填入剩余可退金额，也可以改成较小金额。
4. 点击「商品损坏」「没货」「商品不新鲜」「漏送商品」「错送商品」「商品质量问题」「协商退款」，或直接输入原因；快捷原因选中后仍可编辑，最多 200 字。
5. 核对确认框中的订单、商品、金额及原因，确认后提交微信退款。

列表保留商品明细。用户小程序「订单详情 → 退款记录」显示商家主动退款、商品/规格、每项退款金额、完整原因及退款状态。

## 金额和状态规则

- 金额单位为分。按商品行分摊订单优惠，分币尾差计入后续商品，所有商品净额总和与商品实付一致。
- 退款按商品行和金额执行，不是选择退货件数。明细中的数量是**原购买数量**（支持小数重量），不是声称已退多少件。
- 该入口不退配送费、包装费；系统原有整单退款流程仍保留。
- 按商品部分退款不覆盖订单接单/备货/配送状态，剩余订单可继续履约；累计退款达到整单实付才变成已退款。此功能记录商品退款金额，不自动调整备货数量或回补库存。
- 已成功、待审核、处理中和失败待核实的退款会占用可退额度，拒绝后才释放。不得绕过失败记录再次发起相同金额来“补退”。
- 历史整单退款没有商品对应关系，显示明确提示，同时受订单整体剩余额度约束，不臆造历史商品明细。
- 前后端均校验商品归属、商品/订单剩余额度、重复商品、合计金额；选择变化或过期查询不能沿用旧的核对结果。
- 每次提交带持久化 `requestKey`，相同请求重放返回已有退款单；同一个键更改退款内容会被拒绝。写请求不自动重试，同一表单网络失败后手动重试沿用原键。
- 只有微信确认成功才展示「退款成功」。处理中提示等待确认，失败提示尚未成功，重复回调不累计两次退款。
- 完整自定义原因保存在业务记录中。微信请求摘要按 UTF-8 字符边界截取到 80 字节，避免微信接口拒绝长中文原因。依据：[微信支付申请退款接口](https://pay.wechatpay.cn/doc/v3/merchant/4012791903)。

## 接口

`GET /api/admin/refunds/orders/{orderId}/items`（管理员登录）：

```json
{
  "availableAmount": 2900,
  "hasUnallocatedRefunds": false,
  "items": [
    { "item": { "id": 701, "productName": "番茄" }, "paidAmount": 1000, "availableAmount": 1000 }
  ]
}
```

`POST /api/admin/refunds`（管理员登录，HTTP 入口必须指定商品）：

```json
{
  "userId": 1000,
  "orderId": 123,
  "refundAmount": 456,
  "reason": "没货：番茄售完，其余商品正常配送",
  "items": [{ "orderItemId": 701, "refundAmount": 456 }],
  "requestKey": "每次新退款生成的UUID"
}
```

退款 DTO 新增 `items`，每项包括 `orderItemId/productId/productName/imageUrl/specificationText/saleUnit/quantity/refundAmount`。旧记录缺少该字段时解析为空数组。明细存储于既有状态持久化中，无新增数据库迁移，不修改历史退款结果。

## 验证与发布

```bash
# 后端单元/回归测试（测试环境，不发起真实退款）
cd server
./mvnw test

# 后台构建及隔离浏览器测试（所有 API 均为 mock）
cd ../art-lnb-master
npm run build
PLAYWRIGHT_MODULE=/path/to/playwright node scripts/refund-ui-smoke.cjs

# 小程序数据展示回归
cd ../client-wechat
npm test
```

浏览器脚本验证显式选商品、原因快捷选项及自定义输入、分项金额、POST 不重试、手动重试复用请求键、处理中不误报成功、过期订单查询结果被忽略。截图仅含测试数据，输出在临时目录。

服务端和管理后台发布后即可使用新入口；小程序页面变更**仍需要用微信开发者工具上传、审核并发布**，重启服务器不会自动更新线上小程序。导入 `client-wechat`，使用原正式 AppID，先以体验版检查订单详情中的退款商品和原因，再提交发布。未发布的旧小程序仍可读取原有退款状态和原因，但没有新的商品明细布局。

验收实款退款必须由业务方创建测试订单并确认后发起，不使用历史客户订单代替测试。
